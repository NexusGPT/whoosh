# Capability contract: Whoosh (P1 draft, frozen per wave)

Derived from the signed docs/JOURNEYS.md (57 steps) by architect-p1, 2026-11-07, per REF/native-desktop/capability-contract.md. One row per surface and interaction. Surface names are the roster of docs/DESIGN.md:16. The root commit copies this file into the repo as `docs/CAPABILITY-CONTRACT.md`; a change after that is its own request row.

Rules for reading the rows:
- **reads** names the core type (one per docs/DATA-MAP.md record), where it comes from, and how fresh it must be. `core` = the Rust core's store through a UniFFI stream; Swift never holds a second copy.
- **event** names what fires and who listens. Core events: `InboxChanged`, `CountsChanged`, `ThreadChanged`, `SyncStateChanged`, `OutboxTick`, `SendCompleted`, `ActionFailed{account_name, reason_words, retryable}`, `SearchResults`, `AgentDelta`, `ProposalReady`, `ArrivalNotice`.
- **state** is before → after · on failure.
- **provider**: `local` (core or Swift on the device), `OS` (an Apple framework or service), `hosted` (the push relay, archetype 1; its API rows go in api-surface-contract.md, gap G10), `mail server`, `AI provider` (the user's key), `speech provider`.
- Accessibility ids follow `<surface>.<region>.<element>[.<index>]`, for example `mac-main.list.row.0`.
- Labels nest (owner, 2026-11-07: "labelling and sublabelling (e.g., client>Provanta) and sub-sub-labelling (up to like 3-5 levels)"; request row 2026-11-07, root delta 4). A label carries `parent_id`, `path` (the names from the root down, joined by " > ") and `depth` (1 to LABEL_DEPTH_MAX, docs/CONSTANTS.md: 5). The core read `labels()` returns every label as flat rows, a parent before its children; the UI builds the tree from `parent_id`. The Label command (C-J1.5, C-J2.6, C-J5.6) takes a name or a path: a single name that matches exactly one label anywhere means that label; otherwise the path is read from the root and, when the command asks to create, every missing level is created. A path deeper than LABEL_DEPTH_MAX, or with an empty name, is refused in words ("a label can be at most 5 levels deep; ... has 6"); the rule lives once, in the contract crate's `parse_label_path`.
- Accounts, smart folders, label counts (request row 2026-11-07, root delta 5). `accounts()` rows carry `group` (the sidebar group, None = ungrouped), `paused` (sync off, account still listed) and `backfill` (0.0 to 1.0 share of history synced, None = not started; 1.0 = fully synced). The core read `smart_folders()` returns every smart folder, a parent before its children (`id`, `name`, `rule_words`, `parent_id`). `MailLabel.unread` is the label's OWN unread count, never a rolled-up one: the sidebar sums children from `parent_id` to any depth (LABEL_DEPTH_MAX), so a message is counted once at its own label and once more only in each ancestor's displayed total. Chosen over a separate `labelCounts()` read because the sidebar already reads `labels()` for the tree, and a second read would have to be joined by id and could disagree with the first.
- Label commands, smart folders, contacts, one message (request row 2026-11-07, root delta 6). Commands: `RenameLabel{label_id, name}` (one name, not a path; the subtree's paths follow), `MoveLabel{label_id, parent_id: Option}` (None = top level; the subtree moves with it), `CreateLabel{name, parent_id: Option}` (`created_id` = the new label), `DeleteMessage{message_id}` (the notch's Delete button; no undo entry), `MergeContacts{keep_id, merge_id}`. Depth rule in words: a label is at level parent.depth + 1; creating one above LABEL_DEPTH_MAX (5) is refused ("a label can be at most 5 levels deep; ... has 6"); a move is refused when the deepest label of the moved subtree would pass that limit, when the label would go inside itself or its own subtree, or when the new parent already holds a label of that name; a name already used by a sibling, an empty name and a name holding ">" are refused. `SaveSmartFolder` refuses a name that exists already, case ignored, with "the name exists already". New core reads: `rule_match_count(rule_words) -> u32` (the count shown as "N matches" before saving; every word of three letters or more must be found in a message's sender, subject, preview, body or attachment names), `contact(address) -> Option<Contact>` (any address a merged card holds), `contact_messages(contact_id) -> [InboxRow]` (newest first, across accounts and mailboxes, each row with its `account_id`), `message(message_id) -> Option<Message>` (from name and address, time, attachment names, sign-in code, tracker count), and `InboxRow.sender_address`. `thread()` returns real message ids, oldest first, for the design fixture's open thread too. Fixture core state paths: `smart_folder/<name>/rule`, `smart_folder/count`, `label/<id>/name`, `label/<id>/parent`, `message/<id>/deleted`, `contact/count`, `contact/<id>/addresses`.
- Ask, settings, Decisions, MCP, Welcome, undo, split tabs, composer, notes (request row 2026-11-07, root delta 7). Ask: `Citation` carries `account_id`, `sender_name`, `received_at_ms`; `AskAnswer{kind, text, citations}` is read with `answer(conversation_id)` and a conversation's proposals with `proposals(conversation_id)`; events `AgentStep`, `AgentConsentNeeded`, `AgentStopped`; consent is one yes per off-device provider (`AiProvider.mail_consent_at_ms`, command `GiveAgentConsent`), asked before any mail is read; a send proposal carries `draft_id`. Settings: `NotchSetting.list_shows` (latest|unread), `NotificationSetting.delivery` (None = both), commands `SetNotchSetting`, `SetNotificationSetting`, `SetNotification`, `SetAccountIcon`, `SetAccountColour`. Decisions and MCP: `SaveProviderKey` (the key is a `SecretText`, never printed or read back), `SaveAgentConfig`, `SaveDecisionModel`, `ChooseSpeechEngine`, `PreviewDecisions`, `ApplyDecisionPreview`, `SetMcpGrant`, `SetMcpServer`. Welcome: `SetShortcutPreset`, `ReorderAccounts`. Undo: `UndoAction` gains `RenameLabel`, `MoveLabel`, `CreateLabel`, `DeleteMessage`. Split tabs: `AddSplitTab{name, rule}`, `ReorderSplitTabs`, `SetSplitTabEnabled`, `RestoreDefaultSplitTabs`, read `split_tabs()`. Composer: `signature(address)`, `Message.reply_to_name`, an outbox entry is sent when its undo window ends. Notes: `notes(target)`, `AddNote`, `EditNote`, `DeleteNote`. State paths and fixture rules: docs/lanes/contracts.md "Delta 7".
- Counts: **unread** = unread messages in the tab across the included accounts; **waiting** = inbound threads awaiting the owner's reply. One query each, frozen in the contract crate.
